# 决策 0001：公开网站与私有赛事数据使用独立 Git 历史

- 状态：已被决策 0002 取代
- 日期：2026-08-20

> 2026-08-20 用户进一步明确：这是以开发便利为优先的社区活动，不要求把赛事数据隔离到私有仓库，只要求面向用户的网站不展示胜负等内部明细。当前实施以 `0002-single-repository-build-boundary.md` 为准；保留本文件用于说明决策演变。

## 背景

当前线上原型仓库曾把含 `slotId`、`playerId` 等底层字段的解析资料置于公开 Git 历史。即使后来从当前分支删除，历史提交仍可能保留这些内容。

DSL2 新方案要求公开积分，但内部仍必须保存每局参赛者、身份、胜方、工作人员、别名、纠错原因和复核证据。内部记录的必要性不意味着它们适合公开。

## 决定

采用两个彼此独立的 Git 工作区和仓库：

1. 公开网站工作区：`D:\scdoudizhu-dsl2`
   - 保存网站源码、公开文案、公开赛程、经过净化的积分榜结果和可公开资产。
   - 将来可以推送到公开 GitHub 仓库并由 GitHub Pages 部署。

2. 私有赛事运营工作区：计划使用 `D:\scdoudizhu-dsl2-operations`
   - 保存原始对局、回放索引、平台别名、内部选手 ID、积分流水、人工修正、复核记录和导出日志。
   - 必须使用独立 Git 仓库；若设置远端，远端必须保持私有。

私有工作区通过确定性脚本生成最小公开结果。公开结果经过数据契约校验后，才复制到公开网站工作区并分别提交。两个仓库的提交信息都使用详细中文，分别记录源数据变化和公开发布变化。

## 严格边界

公开仓库允许：

- 公开显示名称。
- 名次。
- 累计总积分。
- 段位。
- 统计截止时间和发布时间。
- 公开赛程、规则、通知和已授权资产。

公开仓库禁止：

- `.rep` 回放和原始回放 ZIP。
- 原始解析 JSON。
- slotId、playerId、房间 ID 或其他底层平台标识。
- 选手别名映射和身份合并依据。
- 报名表、联系方式和私有备注。
- 单局胜负流水和内部复核材料。
- 包含上述数据的临时文件、测试夹具、日志或历史提交。

## 后果

正面影响：

- 公开仓库即使完全公开，也不会因历史提交泄露运营证据。
- 计分纠错可以在私有仓库中保持完整审计链。
- 公开网站只处理稳定、很小的数据契约，构建和展示更可靠。
- 将来更换网站框架不会影响原始数据的保存和复核。

需要承担的成本：

- 每次正式发布积分要在两个仓库分别提交。
- 必须实现导出校验，避免人工复制错误。
- 需要明确谁可以访问私有运营仓库。
- 备份、远端权限和密钥管理要分别配置。

这些成本小于把原始数据错误公开后再清理 Git 历史的风险。

## 执行要求

- 在私有工作区建立前，不把任何 DSL1/DSL2 原始回放或解析数据复制进公开仓库。
- 创建私有工作区时，第一项工作是写入访问边界、忽略规则和数据保留说明，并立即提交。
- 公开导出采用白名单字段，禁止“先导出所有字段再在前端隐藏”。
- 每次公开导出生成唯一导出编号；私有仓库记录该编号对应的源提交，公开仓库只保存编号和公开结果。
- 发布流水线扫描公开构建产物，发现禁止字段或禁止扩展名时直接失败。
