# 决策 0002：DSL2 使用单一公开仓库并以网站构建作为数据边界

- 状态：已采纳
- 日期：2026-08-20
- 取代：决策 0001

## 背景

DSL2 是社区活动，维护效率和低操作成本比建立商业级的数据隔离体系更重要。仓库源码公开不代表所有仓库文件都必须在面向用户的网站中提供入口；即使有人主动阅读 Git 历史或自行分析仓库中的赛事资料，也不属于当前项目需要防范的问题。

用户明确要求先只做 DSL2，不移植 DSL1，并直接上线第一版网站进行真实访问，再依据实际体验持续修改。

## 决定

整个 DSL2 项目使用一个 Git 工作区和一个公开 GitHub 仓库：

- `data-source/` 保存原始对局、解析结果、别名、积分流水、修正和复核资料。
- `references/` 保存方案、地图等只读来源快照与来源登记。
- `src/` 保存页面源码及实际面向网站的数据。
- `public/` 保存会原样发布到网站的下载文件和静态资产。
- `dist/` 是构建产物，不纳入 Git。

赛事资料可以进入公开仓库，不再要求建立 `D:\scdoudizhu-dsl2-operations` 或任何私有远端。构建校验仍需保证原始胜负、回放、底层平台标识和内部复核信息不被意外复制到用户网站；这项限制针对网站输出，不针对源码仓库。

## 开发原则

1. 只迁移和开发 DSL2；DSL1 历史档案暂停。
2. 内部数据与网站数据用目录和生成步骤区分，不以仓库权限区分。
3. 积分页继续只展示名次、公开显示名、累计积分、段位和统计时间。
4. 原始记录可以提交，但页面、网站 JSON 和下载区不得提供胜负明细或底层标识。
5. 地图等明确面向参赛者的 DSL2 文件放入 `public` 并提供下载和 SHA-256。
6. 访问令牌、账号凭据、私钥和 `.env` 仍不得进入 Git；它们与社区赛事数据不是同一类信息。
7. `main` 分支通过 GitHub Actions 直接部署，依靠在线实测和后续反馈迭代，不等待所有赛事细节一次性确认完毕。

## 后果

正面影响：

- 只维护一个工作区、一条提交链和一个部署入口。
- 赛事资料与导出结果可以在同一提交中追踪，减少复制和同步步骤。
- 网站可以尽快上线，主办方能够根据真实访问体验给出具体反馈。

接受的取舍：

- GitHub 仓库访问者理论上可以阅读或分析未进入网站的赛事资料。
- 仓库体积可能因回放和解析文件增加，需要在实际遇到 GitHub 单文件或仓库容量限制时再处理。
- 必须持续检查构建输入，避免开发时误把内部数据放进 `src` 或 `public`。

这些取舍已经由用户明确接受，后续工作不得再次以隐私隔离为由阻止 DSL2 的正常开发和上线。
